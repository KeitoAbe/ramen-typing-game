# ドキュメントの読み方

`docs/` には、**現行のルール（正本）** と **書いた時点の記録（スナップショット）** の 2 種類がある。
どちらに属するかで信頼してよい度合いが違うので、何かを調べる前にこのファイルを読むこと。

| 分類 | 置き場所 | 扱い |
|------|---------|------|
| 正本 | `docs/` 直下 | 現行の根拠にしてよい。実装と食い違っていたら、どちらかのバグなので指摘する |
| スナップショット | `docs/notes/` | 設計メモ・要件・実装計画。書いた時点の記録で、その後は更新しない。現行の根拠にしない。実装と食い違ったら実装が正 |

## 正本の一覧

| ファイル | 内容 |
|---------|------|
| [analytics.md](analytics.md) | GA4 に送るカスタムイベントの名前・送るとき・パラメータの一覧 |
| [architecture.md](architecture.md) | アプリのコード構成とレイヤーのルール |
| [design.md](design.md) | 画面の見た目（書体・面・色）の使い分けの規則 |
| [loop-engineering.md](loop-engineering.md) | ループの運用ルール（判定順、ラベル、CodeRabbit の扱い、GitHub 側のセットアップ） |
| [loop-session-rules.md](loop-session-rules.md) | ループの各セッションに共通する規則 |

## 書き足すときのルール

1. 設計メモや実装計画は `docs/notes/` に、`YYYYMMDD_HHMM_タイトル.md` の名前で置く。
2. ルールを定める文書を新しく作るときだけ `docs/` 直下に置き、上の一覧に追加する。
3. 古くなったスナップショットは消さない（なぜその設計になったかを追うための履歴として残す）。
